# 사람이 Crop 범위를 점검·조절하는 방법

검수 목록은 `outputs/adaptive_crop_full_v1/manual_crop_review.csv`다. **1,757장, 30품목**이며 이미지 경로, 검수 이유, 기존 C 좌표, 미검증 자동 후보, 참조 제품 BBox와 마스크 경로를 포함한다. 이 파일은 검수 전용이다. 모델 전처리 입력으로 직접 사용하지 않는다.

현재 전체 전처리 CSV는 `preprocessing_metadata.csv`이며 151,050장 모두 원본 전체를 유지한다. 자동 후보가 안전하다고 판정해 Crop한 것은 아니다.

## 실행

Ubuntu 프로젝트 루트에서:

```bash
cd ~/MV
uv run --offline python scripts/review_crop_ranges.py --check
uv run --offline python scripts/review_crop_ranges.py --port 8769
```

Windows 브라우저에서 `http://127.0.0.1:8769`를 연다. 기존 제품 BBox 검수 서버의 8766·8767 포트와 별도다. 포트가 사용 중이면 다른 포트를 지정하며 기존 프로세스를 임의로 종료하지 않는다.

`--check`의 `total`은1,757, 실제 Crop 승인 전 `verified`는0이다. 여기서 승인 수는 `APPROVED_CROP`이며 제품 GT `VERIFIED_GT`와 다르다.

## 화면과 검수 순서

1. 원본 이미지와 품목·시점·제품 ID·Split·검수 이유를 확인한다. 우선순위가 높은 사례부터 정렬돼 있다.
2. 녹색은 현재 Crop, 파란 점선은 미검증 자동 후보, 청록은 검수된 제품 BBox 참조다. 결함 마스크가 있으면 자홍색으로 겹쳐 볼 수 있다.
3. 마우스로 드래그해 Crop 범위를 지정한다. 기본은 정사각형이며 체크를 끄면 직사각형도 가능하다. 원본 좌표와 끝 좌표 exclusive를 사용한다. 경계는 정수 픽셀로 표시한다.
4. `자동 후보 불러오기`는 후보 좌표만 불러오며 승인하지 않는다. `원본 전체 유지`는1024 전체 범위로 복원한다.
5. `현재 범위 보존 점검`을 누른다. 제공된 제품 BBox 면적과 결함 픽셀 보존 결과를 읽고 제품·결함이 실제로 포함됐는지 직접 확인한다. GT가 없으면 UNVERIFIED/NOT_PROVIDED로 표시되며 안전한 것으로 간주하지 않는다.
6. 관측 손실 또는 미검증 경고가 있으면 별도 확인 체크가 필요하다. 손실이 관측되면 우선 범위를 넓히거나 원본 유지로 복원하는 것을 권장한다. 범위를 바꾼 후에는 해당 좌표에 맞는 보존 점검이 있어야 승인된다.
7. 검수자 이름, 직접 확인을 입력하고 `승인·저장`한다. 판단을 미루거나 후보를 거부하려면 이유와 함께 보류·거부한다. 이미지가 보이지 않거나 좌표가 유효하지 않으면 승인할 수 없다.
8. `다음 미승인`으로 이어가거나 번호를 입력해 이동한다. 이미 승인한 항목을 수정할 때는 재검수 체크가 필요하며 기존 이력은 보존된다.
9. `검수 반영한 새 전처리 CSV 만들기`를 누른다. 출력 경로와 반영된 수동 승인 수를 확인한다.

검수 목록의 이유는 서로 겹친다. 이미지 Gate 위험438장, GrabCut 후보 제품 손실15장, Center896 제품 손실121장, 이전 Gate 제품 손실6장, 후속 추가 CenterCrop 시 마스크 손실1,111장과 기존 검토 표본588장의 합집합이다. 특히 추가 CenterCrop 위험은 **현재 C 원본 유지가 실패했다는 뜻이 아니다.** 이 목록이 전체151,050장의 모든 위험을 검증해 찾아낸 목록인 것도 아니다. 나머지는 원본 유지이며, 더 Crop하려면 추가 검수 범위를 구성해야 한다.

## 승인 결과와 전처리 CSV

- Crop 승인 이력: `outputs/adaptive_crop_full_v1/manual_crop_review_ledger.jsonl`
- 원본 전체 전처리 CSV: `outputs/adaptive_crop_full_v1/preprocessing_metadata.csv` — 수정하지 않음
- 수동 승인 반영본: `preprocessing_metadata_reviewed_v1.csv`, 다음 내보내기는 `v2`, `v3` 순으로 새 파일 생성
- 사람 제품 GT Ledger: 기존 `human_approved_gt.jsonl` — 이 도구는 쓰지 않음

새 반영본도151,050행이다. 최신 `APPROVED_CROP` 좌표만 반영하고 미검수·보류·거부 항목은 기준 C로 유지한다. 실제로 줄인 수동 범위는 `selected_policy=HUMAN_CROP`이며 자동 A/B로 위장하지 않는다. 수동으로 전체를 확인한 행은 C이면서 수동 검수 상태를 남긴다. `VERIFIED_GT`는 생성하지 않는다.

내보낸 CSV에는 기존 좌표·경로 필드를 유지하면서 검수자·시각·경고 확인·축별 확대율 등 수동 이력 필드를 추가한다. 직사각형의 `geometric_gain`은 원본 면적/Crop 면적의 제곱근이고 `gain_x`, `gain_y`로 두 축을 따로 확인한다. 실제 제품·결함 보존 또는 모델 성능이 검증됐다는 의미는 아니다.

전처리할 때는 **가장 최근에 직접 내보낸 반영 CSV 하나**를 사용한다.

```python
from mv_analysis.crop_manifest import iter_metadata, load_crop_rgb

for row in iter_metadata("outputs/adaptive_crop_full_v1/preprocessing_metadata_reviewed_v1.csv"):
    rgb = load_crop_rgb(row)
    # 이 다음에 모델별 Resize/Normalize를 한 번 적용한다.
```

위 v1 파일은 실제 검수 후 버튼을 눌러야 생성된다. 아직 승인하지 않았는데 수정된 CSV가 이미 있다고 가정하면 안 된다. 원본 이미지 파일은 필요하다. Crop 이미지 파일은 이 도구에서 생성하지 않는다.

## 정답 참조와 평가 주의

제품 GT와 결함 마스크는 **사람 검수와 사후 점검**에만 사용하며 자동 생산 Gate가 이를 보고 좌표를 고르지는 않는다. GT 참조는600개 승인 스냅샷 기준이다. GT가 없는 제품 외곽과 표시되지 않은 결함은 사람이 확인해야 한다.

Test에서 제품 GT·마스크 참조로 수동 Crop을 조절한 행은 정답 보조 검수 및 평가 오염 검토 플래그를 기록한다. 이런 행을 완전히 독립적인 전처리·최종 평가라고 주장하면 안 된다. 원본·기준CSV·과거 승인 기록은 보존해 비교할 수 있다.

## 오류와 검증

로딩 실패는 `다시 불러오기`를 사용한다. 오래된 JSON/이미지 응답은 새 항목에 덮어쓰지 않는다. 보존 점검 후 다른 좌표로 바꾸면 승인이 차단된다. 다른 창에서 수정됐으면 새로 불러온 뒤 재검수한다. 동일 승인 재전송은 중복 이력을 추가하지 않는다.

실제1,757개 항목의 표준 JSON, 정수 좌표, 이미지와 마스크 표시 API, 보존 점검 API를 읽기 전용으로 검사했다. 승인·CSV 반영·재검수·중복·손실 확인은 임시 데이터와 임시 Ledger에서만 테스트했다. 실제 Crop 승인0개이며 제품 GT를 변경하지 않았다. Node DOM 모의 검사15개를 통과했지만 실제 Chromium/Windows 화면 검증은 아직 UNVERIFIED다.

## 하늘색 제품 박스가 있는 항목

하늘색은 이미 승인된 제품 GT다. 이 제품 박스를 다시 그릴 필요는 없다. 미승인 항목에 제품 GT가 있으면 GT+10% Crop 후보와 보존 점검을 자동 실행하도록 했다. `기존 승인 제품 GT +10% Crop` 버튼으로 다시 불러올 수도 있다. 현재 검수 목록에서 해당 항목은173개이며 전체600개 후보는 별도 `gt_reference_crop_candidates.csv`에 있다.

기존 승인된 Crop 범위는 자동 후보로 덮어쓰지 않는다. 페이지 코드를 새로 적용하려면 편집 중인 내용을 먼저 저장한 뒤 새로고침한다. 다음으로 이동만 하면 새 Crop 승인으로 기록되지 않는다. 실제 반영은 명시적 승인과 새 CSV 내보내기로 진행한다. 자동 GT 재사용의 제품600개·제공 마스크199개 검사는 모두 보존됐고, 마스크 없는401개는 결함 픽셀 평가NA다.
